O registry público usa distribuição por source: a CLI shadcn copia cada
componente para o projeto, instala as dependências declaradas e injeta somente o
adapter CSS necessário. O pacote estável `ds-tis` continua entregando tokens e
visual.

<Aside type="caution" title="Beta com canal versionado">
  O canal `/registry/v1` mantém URLs previsíveis, mas a API React ainda pode
  receber ajustes compatíveis antes de uma promoção estável. Não instale
  `@tis/react`: esse pacote não é público.
</Aside>

## 1. Configure o namespace

Adicione o registry ao `components.json` do projeto:

```json
{
  "registries": {
    "@tis": "https://tis-experience.github.io/ds-tis/registry/v1/{name}.json"
  }
}
```

O restante da configuração shadcn (`style`, `tsx`, aliases e caminho do CSS)
permanece sob controle do projeto consumidor.

`@tis/tis-base` configura a base compartilhada quando um projeto precisa
instalá-la explicitamente. Os componentes já carregam as dependências e o helper
necessários, portanto ela não é um pré-requisito manual para a instalação comum.

## Uso em agents IA

Leia primeiro:

1. `docs/api/consumer-context.json` para descobrir tecnologias e registry;
2. `docs/api/components.json` para selecionar apenas componentes com
   `implementations.react.status: "beta"`;
3. `implementations.react.item` para formar o comando `@tis/<item>`;
4. a página Web do componente para decisões visuais e de conteúdo;
5. o source instalado para a API React efetivamente copiada no projeto.

Se o status for `unavailable`, use a implementação Web CSS ou declare uma
adaptação local. Não invente um item do registry nem um export de `@tis/react`.

O manifesto compacto está em
`https://tis-experience.github.io/ds-tis/registry/manifest.json`. Cada item
também pode ser instalado pela URL direta, por exemplo:

```bash
npx shadcn@latest add https://tis-experience.github.io/ds-tis/registry/v1/button.json
```
