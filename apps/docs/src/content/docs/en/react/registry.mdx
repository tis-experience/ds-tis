The public registry uses source distribution: the shadcn CLI copies each
component into the project, installs declared dependencies, and injects only the
required CSS adapter. The stable `ds-tis` package continues to provide tokens
and visual language.

<Aside type="caution" title="Beta with a versioned channel">
  The `/registry/v1` channel keeps addresses predictable, but the React API may
  still receive compatible adjustments before stable promotion. Do not install
  `@tis/react`: that package is not public.
</Aside>

## 1. Configure the namespace

Add the registry to the project's `components.json`:

```json
{
  "registries": {
    "@tis": "https://tis-experience.github.io/ds-tis/registry/v1/{name}.json"
  }
}
```

The remaining shadcn configuration (`style`, `tsx`, aliases, and CSS path)
stays under the consumer project's control.

`@tis/tis-base` configures the shared base when a project needs to install it
explicitly. Components already carry their required dependencies and helper, so
it is not a manual prerequisite for common installation.

## Usage by AI agents

Read these sources first:

1. `docs/api/consumer-context.json` to discover technologies and the registry;
2. `docs/api/components.json` to select only components with
   `implementations.react.status: "beta"`;
3. `implementations.react.item` to form the `@tis/<item>` command;
4. the component's Web page for visual and content decisions;
5. the installed source for the React API actually copied into the project.

If status is `unavailable`, use the Web CSS implementation or declare a local
adaptation. Do not invent a registry item or an `@tis/react` export.

The compact manifest is available at
`https://tis-experience.github.io/ds-tis/registry/manifest.json`. Each item can
also be installed by its direct URL, for example:

```bash
npx shadcn@latest add https://tis-experience.github.io/ds-tis/registry/v1/button.json
```
